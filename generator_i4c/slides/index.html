Problem Statement

Recover position after navigation drift

A wafer inspection tool loses track of where it is. It has a small high-resolution Reference patch (where it thinks it should be) and a larger, lower-resolution Search image (what the stage can currently see).

  • Find where the Reference patch appears inside the Search image
  • Output: the match center pixel coordinates
  • Real tools do this to recover from stage/beam drift without a full re-scan
Given
  • Reference image — small, high-res patch
  • Search image — large, lower-res field of view
Find
  • (x, y) — center of the matching region, in Search-image pixels
The Core Challenge

No dataset is provided

The hackathon gives you the problem statement — not the images. Every team has to build their own physically-grounded synthetic Reference/Search pairs before they can train or even test a matching algorithm.

This repo is a turnkey generator for exactly that: DRAM-style and FinFET-style semiconductor structures, rendered at the correct pixel scale, with real SEM acquisition artifacts — and ground truth coordinates handed to you for free.

What's Actually Being Drawn

Each structure is a small layer stack

Real DRAM cells build up bottom-to-top: substrate/active area → word-line (gate poly) → bit-line metal → storage-node contact. Real FinFETs: substrate → fin → gate stack → contact.

  • The generator draws a simplified 3–4 layer stand-in per architecture — not every real process step
  • Each layer is individually inspectable (return_layers=True) for QA and for teaching
  • Flattened painter's-algorithm composite (bottom→top) is exactly what feeds the SEM imaging pipeline

Generate your own: python visualize_layers.py --architecture dram_1x

Large-Scale Composition

Real dies aren't one uniform pattern

A real memory device is built from discrete sub-array mats, separated by strips of visually distinct material — peripheral circuitry, sense-amp/decoder rows, global routing, scribe lines.

  • The fine canvas tiles independently-generated mats, each drawn from a randomly chosen preset of the same architecture
  • Mats are separated by flatter strip regions with sparse routing lines — a different "material" look
  • Cyan boxes: mat boundaries · purple box: the Reference crop's ground-truth location

Configurable via mat_size_nm / strip_width_nm — from a dense patchwork of small blocks to a few large mats.

Large-Scale Composition

Crops that straddle a boundary, on purpose

Sampling the Reference crop uniformly at random mostly lands deep inside one uniform mat — the easy case. Real navigation-recovery often has to match a patch that spans two different regions.

  • boundary_bias sets the probability of deliberately centering the crop across a mat/strip edge
  • Produces harder, more realistic matches: part periodic structure, part flat/routing material
  • Default 0.35 — tune per experiment, or force it to 1.0 for a guaranteed edge case

SEM Imaging Realism

Two physically distinct kinds of artifact

Structural defects are a property of the device, applied once. Acquisition artifacts are a property of the imaging, applied separately per image.

Structural Defects

Pattern collapse & bridging

High-aspect-ratio lines can topple and stick to their neighbor (resist/fin collapse from capillary forces). Applied once to the fine canvas, so it shows up consistently in both derived images.

  • Gaps ≥ threshold: never collapse
  • Gaps < threshold: collapse with 70% probability (mirrors real process variation)
  • Default threshold = 10 nm — exactly 1 px at the Search image's 10 nm/px resolution

Gaps at/above 10nm never collapse (by construction). Below that, it's probabilistic — not every small gap bridges.

  • corner_rounding_px — morphological open/close pass; real lithography/etch never produces perfectly sharp polygon corners (shown at left: rounded)
  • Both stack on top of each pattern's own per-instance width jitter
Acquisition Artifacts

Beam spot & astigmatism

circular beam spot (astigmatism_ratio = 1.0)

elliptical beam spot (astigmatism_ratio = 2.4)

A single physical beam (beam_spot_size_nm, default 5nm) is applied as a Gaussian PSF blur before any downsampling. A real beam is rarely perfectly round — astigmatism_ratio stretches it, producing sharper detail along one axis than the other.

Acquisition Artifacts

Shot noise & detector noise

high dose (~1e6) — near noise floor

low dose (250) + detector noise σ=4

Poisson shot noise: dose is a proxy for electron count/dwell time — higher dose (slower, careful scan) means less relative noise. Detector/readout noise: additive Gaussian on top, independent of dose.

Acquisition Artifacts

Raster drift & jitter

no shear, no jitter

progressive shear + per-row jitter

Progressive row-to-row shear (drift accumulating over scan time) plus per-row jitter (vibration) — a real raster-scan artifact. Applied more strongly to the Search image (slow wide-area scan) than the Reference (fast, careful capture).

Acquisition Artifacts

Vignetting, contrast, lens & charging

vignette 0.85 + gamma 1.8

barrel distortion k=0.12

charging streaks

  • Vignetting — radial darkening from off-axis collection efficiency falloff
  • Gamma — nonlinear detector gain / contrast mis-calibration
  • Barrel/pincushion distortion — imperfect beam-scan linearity
  • Charging streaks — local sample charging on insulating regions, common on real oxide/dielectric areas
A Free Consequence, Not a Parameter

Why dense structures look "unfocused"

same patch, native 1 nm/px

downsampled to 10 nm/px

DRAM/FinFET cell pitch (≈36–96nm) becomes only 3–5 px at the Search image's 10nm/px resolution — below what that sampling rate can faithfully resolve. The periodic structure aliases into a near-random-looking texture. This is not a separate "search blur" fudge factor — it falls straight out of the shared beam blur plus the 10× downsample.

Dataset Format

Sample families: one scene, many acquisitions

generate_sample_family() fixes one structure and one Reference crop, then renders several Search images under different acquisition conditions (clean, low-dose, heavy drift, speckle/impulse noise, charging). Same ground truth throughout — the point is that one Reference should stay findable across a range of degraded Search conditions, not just the exact image it was cut from.

Baseline Solution

Multi-scale template matching

A classical (non-learned) baseline, matching the exact submission interface: takes a reference + search path, prints predicted x,y.

  • Downsample the reference by a candidate scale (searched around 10×, not hardcoded)
  • cv2.matchTemplate(..., TM_CCOEFF_NORMED) — this is ZNCC (zero-mean normalized cross-correlation); baseline_solution/zncc.py exposes it under its proper name with a confidence score
  • Keep the best-scoring location across scales
for scale in (9.0, 9.5, 10.0, 10.5, 11.0):
    template = resize(reference, 1/scale)
    result = cv2.matchTemplate(
        search, template, TM_CCOEFF_NORMED)
    keep best score across scales

# python baseline_solution/infer.py \
#   --reference ref.png --search search.png
#   -> "746.00,326.00"

How the baseline degrades with noise

30 samples/level, mixed DRAM/FinFET presets, baseline_solution/evaluate.py. Real run, not illustrative — expect noise in the trend itself at this sample size, and note the general fall-off is not perfectly monotonic, consistent with the periodic-matching ambiguity on the next slide.

A Real Limitation, Found by Testing

Naive matching struggles on periodic structure

DRAM/FinFET patterns repeat every 3–5 px at Search resolution. A naive global cross-correlation search can lock onto the wrong periodic repeat — a genuine matching-ambiguity limitation, not a generator bug.

Verified directly: the Search image really does contain the true downsampled Reference at the stated ground-truth box (pixel-level diff confirms it). The baseline's global-argmax search is what fails on highly periodic tiles — worth raising with students as a limitation of naive template matching.
